# Альфа-Брифинг — frontend

Веб-интерфейс сервиса новостной аналитики внутри Альфа-Бизнеса. Он показывает руководителю компании события, которые могут повлиять на её работу: персональные инсайты, объяснение их значимости, доступные расчётные показатели и ссылки на источники. Из разбора можно задать уточняющий вопрос AI-помощнику.

Фронтенд отвечает за пользовательский сценарий и отображение данных. Профиль клиента, подбор новостей, подготовка выводов и ответы агента приходят из внешних сервисов через AuthGateway.

## Возможности

- Главная страница интернет-банка с постоянной точкой входа в «Брифинг»; в шапке отображаются компания и пользователь из API.
- Главная брифинга с последними инсайтами и переходами к ленте и агенту.
- Лента персональных и общих инсайтов: сортировка по времени, категории, постраничная загрузка, состояния загрузки, пустого списка и ошибки.
- Страница инсайта: вывод, важность для компании, подтверждённые показатели и доступные источники с переходом к оригиналу. Для демонстрационных инсайтов предусмотрен расширенный разбор с рисками, возможностями, вариантами решений и отдельно обозначенными выводами AI и позицией банка.
- Помощник по открытому инсайту и отдельный чат: уточняющие вопросы, потоковый ответ, остановка генерации, история, архивирование и восстановление диалогов.
- Страница компании: профиль, участники кабинета и база знаний. Создатель компании может добавлять текстовые материалы и редактировать профиль знаний; другие участники видят его без права изменения.

Интерфейс показывает содержимое ответа API. Если в ответе нет позиции банка, рекомендаций, показателей или ссылки на источник, фронтенд не создаёт эти сведения самостоятельно.

## Технологии

| Технология | Применение |
| --- | --- |
| React 19, TypeScript 6 | Компоненты и типы данных |
| Vite 8 | Локальный сервер и сборка |
| React Router 8 | Маршруты и защита страниц сессией |
| TanStack Query 5 | Запросы, кеширование, пагинация, состояния загрузки и ошибок |
| `@flue/sdk`, `@flue/react` | Диалоги и потоковые ответы AgentService |
| CSS Modules, CSS-переменные | Стили экранов и общие дизайн-токены |
| `@alfalab/icons-glyph`, Lucide | Иконки |
| MSW | Демонстрационные ответы при `VITE_USE_MOCKS=true` |

Зависимости зафиксированы в `package-lock.json`. Требуется Node.js 22 или новее и npm.

## Запуск

```sh
npm ci
npm run dev
```

Откройте `http://localhost:5173`. По умолчанию приложение использует живой API `https://api.cheremha.ru`; для входа нужны действующие учётные данные. Dev-сервер Vite проксирует `/api/*` на AuthGateway, удаляя префикс `/api`.

| Команда | Назначение |
| --- | --- |
| `npm run dev` | Локальный сервер |
| `npm run build` | Проверка TypeScript и сборка в `dist/` |
| `npm run preview` | Просмотр собранной версии |

### Конфигурация

Переменные можно задать в `.env.local`:

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `VITE_API_URL` | `/api` | Базовый путь для AuthService, UserService, CompanyService и InsightService |
| `VITE_AGENT_SERVICE_URL` | `/agent-service` | Базовый путь AgentService и потокового чата |
| `VITE_GATEWAY_URL` | `https://api.cheremha.ru` | Цель прокси `/api` только в локальном Vite |
| `VITE_USE_MOCKS` | `false` | Демонстрационные инсайты и MSW |

Например, для локального AuthGateway:

```dotenv
VITE_GATEWAY_URL=http://localhost:8080
```

Для просмотра демонстрационных инсайтов добавьте `VITE_USE_MOCKS=true`. В этом режиме карточки и разборы берутся из `src/entities/insight/model/demo-insights.ts`. Вход, данные пользователя и компании по-прежнему требуют работающих сервисов. Демонстрационные банковские счета и операции на главной странице не подключены к банковскому API.

## Маршруты

| Путь | Экран |
| --- | --- |
| `/login` | Вход |
| `/` | Главная Альфа-Бизнеса и вход в брифинг |
| `/briefing` | Главная брифинга и последние инсайты |
| `/briefing/feed` | Лента инсайтов |
| `/briefing/insights/:kind/:id` | Разбор инсайта (`kind`: `personal` или `general`) |
| `/company` | Профиль компании, участники и база знаний |
| `/chat`, `/chat/:id` | Новый или существующий диалог с агентом |

Все маршруты, кроме `/login`, защищены `RequireSession`. Неизвестный путь открывает страницу 404. Также поддерживаются совместимые маршруты `/alfa-business` и `/briefing/insights/:id`.

## API

Все обычные запросы отправляются через `src/shared/api/client.ts`. Access-токен из `localStorage` добавляется как `Authorization: Bearer <token>`. Для входа токен намеренно не отправляется. Ответы сервера преобразуются в типы фронтенда в слоях `entities/*/api` и `entities/*/model`.

| Сервис | Метод и путь после прокси | Использование |
| --- | --- | --- |
| AuthService | `POST /auth-service/login` | Вход по `{ email, password }`; ответ `{ accessToken, refreshToken }` |
| UserService | `GET /user-service/users/:id` | Имя и роль пользователя |
| CompanyService | `GET /company-service/companies/me` | Текущая компания |
| CompanyService | `GET /company-service/companies/me/members` | Участники кабинета |
| CompanyService | `GET`, `PUT /company-service/companies/me/knowledge` | Чтение и сохранение профиля знаний |
| CompanyService | `GET`, `POST /company-service/companies/me/materials` | Список и добавление текстовых материалов |
| CompanyService | `GET /company-service/companies/me/materials/:materialId/versions/:versionId` | Текст конкретной версии материала |
| InsightService | `GET /insight-service/insights?kind=personal\|general&limit=20&cursor=…` | Лента с курсорной пагинацией; при необходимости передаётся `category` |
| InsightService | `GET /insight-service/insights/:kind/:id` | Разбор выбранного инсайта |
| AgentService | `GET`, `POST /chats`; `GET`, `PATCH /chats/:id` | Список, создание, переименование, архивирование и восстановление диалогов |
| AgentService | `/agents/assistant/:chatId` | История, отправка сообщений, потоковый ответ и остановка через Flue SDK |

Запись профиля знаний и добавление материала передают заголовок `Idempotency-Key`. Список инсайтов запрашивается отдельно для `personal` и `general`, затем результаты объединяются и сортируются по времени. Категории ответа API (`risk`, `opportunity`, `event`) преобразуются в подписи интерфейса.

### Сессия и ошибки

`POST /auth-service/login` возвращает пару токенов. Фронтенд извлекает ID пользователя из claim `UserId` access-токена и хранит access-токен в `localStorage`. Защищённые страницы без сессии перенаправляют на `/login`. При ручном выходе сессия и кеш запросов очищаются; ответ `401` обычного API сбрасывает сессию. Автоматического обновления access-токена пока нет: после истечения срока действия требуется повторный вход.

В чате используется пользовательский JWT из сессии. При необходимости на странице чата можно вручную указать JWT для AgentService; он сохраняется в `sessionStorage` текущего браузерного сеанса. Для потоковых ответов прокси должен пропускать SSE без буферизации.

## Структура проекта

Проект организован по Feature-Sliced Design:

```text
src/
├── app/       инициализация, маршруты, layout, TanStack Query, моки
├── pages/     страницы приложения
├── widgets/   крупные блоки страниц, включая ленту и банковскую навигацию
├── features/  действия пользователя: вход, фильтр, чат с агентом
├── entities/  session, user, company, insight, chat: типы и API
└── shared/    API-клиент, конфигурация, общие UI-компоненты и утилиты
```

Структура ориентирована на направление зависимостей `app → pages → widgets → features → entities → shared`. Алиас `@/` указывает на `src/`. Основные пути приложения собраны в `src/shared/config/routes.ts`.

## Проверка пользовательского сценария

1. Запустите фронтенд и доступные бэкенд-сервисы; подготовьте пользователя с компанией и инсайтами.
2. Войдите на `/login` и на главной Альфа-Бизнеса откройте «Брифинг».
3. Проверьте имя компании в шапке, последние инсайты и переход к полной ленте.
4. Откройте персональный инсайт: проверьте объяснение значимости, доступные показатели и ссылки на источники.
5. Задайте уточняющий вопрос по инсайту и проверьте потоковый ответ агента.
6. Для проверки персонализации войдите под другим тестовым пользователем с другой компанией и сравните ленты. Переключателя компании внутри одной сессии сейчас нет.

Демонстрационные инсайты позволяют показать расширенный вид разбора, но не заменяют проверку сквозного сценария на живых сервисах и данных. Текущий ответ InsightService отображается в упрощённом виде: отдельные блоки позиции банка, рисков, возможностей и шагов AI в нём не подключены. Для их показа на живых данных потребуется соответствующий контракт API и отображение этих полей. Качество отбора и обоснованность выводов зависят от бэкенда.

## Сборка и размещение

`npm run build` создаёт статические файлы в `dist/`. Для самостоятельного размещения настройте SPA fallback на `index.html`, прокси `/api/*` на AuthGateway с удалением префикса `/api` и прокси `/agent-service/*` на AgentService через gateway. Для SSE отключите буферизацию ответа. В `vercel.json` уже заданы rewrite-правила для API, AgentService и клиентских маршрутов.

### Обновления инсайтов по WebSocket

После входа фронтенд получает одноразовый ticket через `POST /api/insight-service/insights/ws-ticket` и открывает один WebSocket на пользовательскую сессию. Он отвечает на heartbeat, перечитывает ленту после `ready` и разрыва соединения, загружает изменённые карточки через GET и получает новый ticket при каждом переподключении. В режиме `VITE_USE_MOCKS=true` соединение не открывается.

По умолчанию браузер подключается к `ws(s)://<origin фронта>/api/insight-service/insights/ws`. Локальный Vite проксирует upgrade на Gateway и выставляет ему соответствующий `Origin`. Для размещения по адресу `https://alfa-briefing.vercel.app` требуется проверить, что production proxy пропускает WebSocket upgrade и передаёт Gateway совместимые `Host` и `Origin`; существующее HTTP rewrite в `vercel.json` само по себе этого не подтверждает. Альтернатива после согласования точного origin с сервером — задать `VITE_INSIGHT_WS_URL=wss://api.cheremha.ru/insight-service/insights/ws` при сборке. Ticket и JWT в URL не добавляются.
